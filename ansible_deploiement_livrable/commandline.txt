Idempotence

Le rôle est conçu pour être idempotent.

En particulier, le schéma PostgreSQL n'est importé que si la table dbversion n'existe pas.

Un second lancement du playbook ne doit donc pas réimporter le schéma Zabbix.
Sécurité

Le mot de passe PostgreSQL ne doit jamais être placé directement dans :

    defaults/main.yml

    vars/main.yml

    les templates

    inventory.ini

Il doit être stocké dans Ansible Vault ou fourni par une autre source de secrets.
Production

Pour une infrastructure importante :

    placer PostgreSQL sur un serveur séparé ;

    mettre Apache derrière un reverse proxy HTTPS ;

    utiliser TLS ;

    utiliser un certificat valide ;

    sauvegarder régulièrement PostgreSQL ;

    surveiller les logs Zabbix ;

    dimensionner PostgreSQL selon le nombre d'hôtes et d'items ;

    utiliser TimescaleDB si nécessaire pour les environnements importants ;

    utiliser Zabbix Agent 2 si les plugins modernes sont nécessaires ;

    ne pas exposer PostgreSQL sur Internet ;

    limiter les ports 10050/10051 avec un firewall ;

    utiliser des secrets externes pour les mots de passe ;

    tester les restaurations des sauvegardes ;

    versionner le rôle et les collections Ansible.

Recommandations de production

Pour un serveur de production, je modifierais surtout l'architecture plutôt que le principe du rôle :

    PostgreSQL séparé pour les installations importantes.

    HTTPS obligatoire pour le frontend.

    Firewall :

        TCP 80/443 depuis les utilisateurs/reverse proxy ;

        TCP 10051 uniquement depuis les Zabbix proxies/agents actifs autorisés ;

        TCP 10050 uniquement depuis le serveur Zabbix ;

        PostgreSQL 5432 non exposé publiquement.

    Sauvegarde PostgreSQL quotidienne avec tests de restauration.

    Ansible Vault ou gestionnaire de secrets externe pour DBPassword.

    Ne pas mettre le mot de passe PostgreSQL dans Git.

    Pour une grosse volumétrie, dimensionner PostgreSQL (shared_buffers, work_mem, WAL, connexions, stockage SSD).

    En environnement Zabbix important, étudier TimescaleDB et le partitionnement.

    Utiliser Agent 2 si les plugins Agent 2 sont nécessaires.

    Épingler la collection Ansible et le major Zabbix dans le dépôt Git.

    Tester le rôle sur une VM Debian 13 avant production.

    Exécuter systématiquement :
